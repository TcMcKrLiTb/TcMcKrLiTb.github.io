在 STM32F746 上跑通手写数字识别

November 9, 2026 - 3 mins read
  • stm32
  • TouchGFX
  • PyTorch
  • Edge AI

今天在 STM32F746G-DISCO 上做了一个手写数字识别 Demo，工程叫 TouchDigit_STM32。左边是一块 256×256 的画板，右边显示识别结果和置信度。屏幕上写一个数字，点 RUN，板子就会用本地模型跑一次推理。下面这张是烧录后写的 5，结果显示为 5，置信度读数是 99.3。

从 NIST SD-19 训练数字模型

下载的是 NIST SD-19 的 by_class.zip。这个包按字符的 ASCII 十六进制编码分目录，30 到 39 对应数字 0 到 9。下面这张截图里的 4a 对应大写字母 J，能看出原始数据里的笔迹大小和位置差别很大。我只取数字目录中的 train_30 到 train_39 训练，测试用独立的 hsf_4 分区。NIST SD-19 用户指南

在 Conda 的 machineLearning 环境里训练了一个两层卷积网络。每层卷积后接 ReLU 和最大池化，最后用全连接层输出 0 到 9 的 10 个分数。输入统一成 28×28 单通道。

训练规模 轮数 完整 hsf_4 测试集
20,000 张，每类 2,000 张 3 92.59%（54,302 / 58,646）
80,000 张，每类 8,000 张 10 97.07%（56,925 / 58,646）

另外从 hsf_4 每类抽 100 张，把同一批图片放到 256×256 的模拟画布上。用灰度画布时准确率是 96.8%，二值画布是 96.5%。这组数据用来检查画布输入和预处理，触屏实机这次做的是功能验证。

导出 ONNX，编进 STM32 固件

把第二轮训练的权重导出成 FP32 ONNX，固定输入为 [1, 1, 28, 28]，输出为 [1, 10]。用 30 个输入对照 PyTorch 和 ONNX 的输出，预测类别全部一致。下图左边是原始 ONNX，右边是 AI Studio 转换后的网络。工具内部把单通道图排成了 1×28×28×1，输入仍然是 784 个浮点数。

用 STM32Cube AI Studio 选 STM32F746G-DISCO 生成 C 代码。这次 AI Studio 的板端运行报告给出的推理时间是 27.56 ms，约 36.28 次/秒。这个时间对应模型推理，整个 RUN 流程还要处理笔迹和更新界面。

CubeMX 用来配置 MCU 和 TouchGFX。模型生成后，直接在工程根 CMakeLists.txt 中把 AI/App/network.c 和 network_data.c 加到目标，加入 AI/App 与 Middlewares/ST/AI/Inc 头文件路径，并链接 NetworkRuntime1210_CM7_GCC.a。之后用 CLion 和 CubeCLT 在原有的 build/debug 里构建。链接报告中，整份固件使用了 204,272 B RAM 和 266,048 B Flash。ST 的库集成与 API 指南

让画板和 RUN 按钮工作起来

烧录复位后，一开始遇到了 Programmer 会话断开和屏幕无画面。我先把显示链路单独跑通，检查 25 MHz HSE、LTDC 时钟和中断，并补齐外部 SDRAM 的启动序列。TouchGFX 的帧缓冲放在 SDRAM，LTDC 中断也需要进入 HAL_LTDC_IRQHandler()。板上能显示 Designer 做的界面，并且 RUN 能响应触摸后，再接模型。

TouchGFX 的画板和模型各用自己的尺寸。FT5336 的触点坐标传给自定义画板，画板把触点之间连起来，同时维护一份 256×256 的笔迹缓存。点 RUN 后走下面这条路径。

256×256 笔迹 → 裁剪边界 → Lanczos3 等比缩放（最长边 20 像素）
             → 居中到 28×28、归一化到 0–1 → STAI 同步推理
             → 取最大分数对应的数字、计算 Softmax → 更新界面

C 版预处理和 Pillow 版对照过 1,000 张样本，单像素最大差值是 1/255，两版的预测类别全部一致。空画板直接显示占位符。一次识别完成后，下次落笔会先清空上一张画板。这样可以连续写、连续试，屏幕上的置信度表示模型对当前这一个输入的分数。
